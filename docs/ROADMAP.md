# 路线图

标注含义：✅ 已实现 · 🚧 进行中 · 💭 计划中 · 🤔 待定（需要验证可行性）

## v1.0（当前）

- ✅ 安卓 → 安卓 / Windows / Linux / macOS / iOS 投屏
- ✅ H.264 硬编硬解，1080p60，最高 1440p
- ✅ 系统音频（AudioPlaybackCapture）+ 音画同步
- ✅ 局域网自动发现、PIN / 二维码连接
- ✅ 反向控制（触摸 + 按键）
- ✅ 自适应码率（读 socket 背压）
- ✅ 断线自动重连、息屏继续推流
- ✅ 完全免费：无广告、无内购、无功能锁

## v1.1 — 延迟再砍一半

- 💭 **UDP + FEC**：目前 TCP 在丢包时会整体卡住（队头阻塞）。改成 UDP + 前向纠错，
  预计端到端从 70ms 降到 35–45ms，且丢包不再卡画面。
- 💭 **QUIC 备选**：`quinn` 有成熟实现，自带拥塞控制与多路复用，省掉自己写 FEC 的坑。
- 🤔 **硬件光标层**：把鼠标单独当一路小图层传，视频只传变化区域，静止时几乎零码率。
- 💭 **编码器 ROI**：文字区域优先给码率（屏幕内容 70% 是文字）。
- 💭 **HDR / 10bit**：需要 Main10 profile，低端机可能没有硬编。

## v1.2 — 场景扩展

- 💭 **手机当第二屏（扩展模式）**：需要虚拟显示器（Android 上没有官方 API，
  只能靠 MediaProjection 缩放 + 自定义分辨率），可行但要解厂商兼容性。
- 💭 **双向音频**：接收端说话传回手机（会议场景）。
- 💭 **文件拖拽**：从电脑拖文件到手机（走同一 TCP 通道的 FILE 包类型，协议已预留）。
- 💭 **剪贴板同步**：明文同步有风险，需要默认关闭 + 显式开关。

## v2.0 — 多机与协作

- 💭 **一台手机 → 多台同时看**（当前 5 台，协议已支持）
- 💭 **反向投屏**：电脑 → 手机（同一套协议，角色互换）
- 💭 **标注笔**：观看端可以在画面上涂画并回传（教学场景）

## 明确不做

- ❌ 云端中继 / 跨互联网投屏（违背「纯局域网」定位，且带宽成本毁掉商业模式）
- ❌ 账号体系 / 用户画像
- ❌ 广告、内购、试用期限制
- ❌ 任何形式的付费墙、内购、订阅
